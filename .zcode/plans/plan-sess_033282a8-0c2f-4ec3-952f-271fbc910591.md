# 优化对话流「思考 + 工具」渲染：思考合并为单块 + 过程区限高滚动

## 问题根因（已探明）

一轮对话的 block 序列是 `[思考, 工具, 思考, 工具, …, 正文]`，渲染上有三个放大因素：

1. **思考被切成多段卡片**：`mergeAdjacentThinking`（agent-flow-panel.tsx:143）只合并相邻思考段，被工具隔开的每段各成一张折叠卡——一轮 5 段思考 = 5 张卡
2. **流式思考不限高**：`.think-body-live`（globals.css:382）`max-height: none`，思考全文"向下生长"，占满数屏
3. **工具卡平铺**：每个工具调用一张卡（inline-tool-group.tsx:201 明确"无整组折叠"），30 个工具 = 30 行堆叠

用户已选定方向：**① 思考合并为单个折叠块（Claude App 风格）；② 流式期间过程区限高滚动窗口（终端式，自动贴底）**。

## 方案要点

**纯渲染层改造，不动数据模型**——`blocks` 持久化结构、后端 resync、搜索高亮全部不受影响，旧消息直接受益，零迁移风险。

### 1. 新增 `hoistThinkingBlocks` 辅助函数（agent-flow-panel.tsx，放 `mergeAdjacentThinking` 旁 ~143 行）

- 从 block 数组中抽出全部 thinking 块内容（保序），其余块原样保留
- 合并时沿用现有的累积重发去重逻辑（`includes` 判断，同 mergeAdjacentThinking:149-157）
- 返回 `[{type:"thinking", content: 合并文本}, ...其余块]`——单张思考卡置顶，工具流紧随其后

### 2. `ThinkingFold` 增加可选 `streaming` 属性（agent-flow-panel.tsx:200）

- `active`（现有）= 正在生成思考 → 脉冲图标 + "思考中"标题
- `streaming`（新增）= 本轮仍在流式 → `<details open>` 强制展开、body 不限高（复用 `think-body-live` class，即 `active || streaming` 时生效）
- 效果：整轮期间合并思考卡保持可读（在限高窗口内滚动），但只有真正在思考时才显示"思考中"；轮结束后照常收起为一行 `思考 · 时长 · 首句摘要`

### 3. 新增 `ProcessWindow` 组件（agent-flow-panel.tsx，放 ThinkingFold 后 ~272 行）

- `active` 时 `max-height: min(56vh, 26rem)` + `overflow-y: auto`（终端窗口式）
- 贴底跟随：`stick` ref 记录用户是否在底部（距底 <40px），内容更新时仅当贴底才 `scrollTop = scrollHeight`；用户上翻即停跟随，回到底部恢复
- 仅流式路径使用；已完成消息走外层 `<details>` 折叠，无需限高

### 4. 流式渲染路径改造（agent-flow-panel.tsx ~8450-8628）

- `normalizedBlocks` 计算处套一层 `hoistThinkingBlocks`（~8450 行）
- 从 hoist 前的数组计算 `thinkingActiveNow`：从尾部找第一个非 text/file_change 块，是 thinking 则"思考中"脉冲生效，否则仅展开不脉冲
- 顶部 `showStreamThinking` 分支保留（首批思考 buffer 还没成 block 的场景）
- 过程内容容器 `<div className="mt-1 space-y-2">`（~8526 行）→ `<ProcessWindow active={streamingActive}>`
- 合并思考卡传 `streaming={streamingActive}`、`active={thinkingActiveNow}`
- 摘要行加操作计数：`已完成 · 30s · 12 个操作`（复用已导出但未接线的 `summarizeTaskBlocks`:306）

### 5. 已提交消息渲染路径改造（agent-flow-panel.tsx ~1378-1507）

- 同样对 `consolidatedBlocks` 应用 `hoistThinkingBlocks`
- 合并思考卡传 `duration={msg.thinkingTime}`（helix-types.ts:142 已有该字段；实施时核对单位与 `formatDuration` 入参一致，与 `messageDuration` 同口径）
- `showInlineReasoning`（只有 reasoning 无 blocks 的旧消息）分支保持不变
- 摘要行同样加 `· N 个操作` 计数

### 6. CSS（globals.css，`.think-body-live` 旁 ~382 行后）

```css
/* 流式过程区限高滚动窗口（终端式）：思考+工具在固定高度内滚动，
   答案区保持可见；用户上翻即停跟随。 */
.process-window { overflow-y: auto; }
.process-window-live { max-height: min(56vh, 26rem); }
```

## 明确不做

- 不改 block 数据结构/持久化（resync、旧消息零影响）
- 不改工具卡渲染（已是一行一卡紧凑形态，限高窗口已解决堆叠问题）
- 不加用户设置项（customize-panel 无需动；完成态本就折叠，流式窗口是纯改进）
