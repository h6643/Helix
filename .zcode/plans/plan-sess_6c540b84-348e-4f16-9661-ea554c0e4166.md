# pi 配置文件合并清理方案

## 背景与约束

`~/.pi/agent/` 现有 10 个配置文件 + extensions 目录混杂。核心约束：
- **pi 强制文件名**（按名读取，不可合并）：settings.json、models.json、auth.json、trust.json、models-store.json（缓存）
- **pi 生态包约定文件名**（包自己按名读取，不可合并）：mcp.json（pi-mcp-adapter）、hermes-memory-config.json（pi-hermes-memory/src/config.ts:76）
- **Helix 自有文件**：config.yaml（6 个写入者）、.env、vision.json、skill_usage.json（尚不存在）
- 发现 `data_root` 指针（`AppData/Roaming/helix/data_root`）指向 `~/.pi/agent` 本身，所以 Helix 文件与 pi 文件同层混住——这是文件显得杂乱的直接原因，但不改此布局（改动面大且无收益）

## A. 纯文件清理（不动代码，先备份）

**备份**：全部被改文件复制到 `~/.pi/agent/backup-config-20260912/`。

1. **删除死文件**：`extensions/pi-settings.json`（settings.json 的陈旧漂移副本，pi 不读）、`extensions/pi-subagents-package.json`（npm manifest 参考副本，无配置作用）
2. **删除 pi-subagents 死栈**：删 `extensions/pi-subagents-lite.ts`；settings.json 的 extensions 数组移除 `"!extensions/pi-subagents-lite.ts"`（剩 `["!extensions/pi-cron/**", "!extensions/pi-web-access/**"]`）。UI 未来重新启用仍走 npm packages 直载路径（helix.rs:519 else 分支），不受影响。npm/package.json 里的 pi-subagents 依赖**保留**——保护 node_modules 不被后续 `pi install` 清掉，保证"想用再开"的退路
3. **settings.json**：删除整个 `subagents.agentOverrides` 块（10 条禁用项，pi-subagents 根本没加载，纯惯性残留）
4. **models.json 去重**：删 `agnes`（与 agnes-ai 同端点同 key，仅 contextWindow 微差）和 `glm`（与 api.tokenrouter.com 同 URL 同 key，且坏值 contextWindow=1000/maxTokens=256，误选严重劣化）。保留 `agnes-ai`（contextWindow 524288，与 config.rs:321 的 URL→provider 名推导一致）、`api.tokenrouter.com`（当前默认）、`zhipu`（不同端点）
5. **auth.json 键名对齐**：`agnes`→`agnes-ai`、`tokenrouter`→`api.tokenrouter.com`（key 值不变，让 fallback 查找（config.rs:77-95）与实际 provider id 匹配）
6. **config.yaml**：删除死掉的 `custom_providers:` 和 `model:` 块（config.rs:17 注释明确"legacy and ignored"，其中密钥与 settings/models 重复三处）。保留 `agent.service_tier`（UI 活配置）
7. **.env 不动**（用户决定：保留旧 OPENAI 密钥）；**hermes-memory-config.json / mcp.json 不动**（包约定文件）
8. **删除运行时残留**：`D:\Project\Helix\.pi\tasks\` 下 25 个空 session 目录
9. `pi-cron/`、`pi-web-access/` 目录及对应排除项保留（UI 可随时开关的插件）

## B. vision.json → config.yaml 整合（动代码）

`vision.rs` 改为读写 config.yaml 的 `vision:` 块（4 个二级键 `vision.provider / vision.model / vision.baseUrl / vision.apiKey`，复用现有 `set_yaml_key` 的两段式写法 + delegation 同款逐行解析）：

- `read_config()`：优先读 config.yaml `vision:` 块；为空且 `vision.json` 仍存在 → 一次性迁移（折入 config.yaml 后删除 vision.json）
- `vision_config_save`：写 4 个 yaml 键，原子落盘
- 前端 `vision-model-settings.tsx` / IPC 契约不变（provider/model/baseUrl/apiKey 四字段原样）
- 附带：vision.rs 文件头注释更新（去掉"单独 JSON 文件避免 YAML 深合并"的过时理由）

## C. 配置写路径小加固（动代码）

1. **settings.json 单一读写入口**：config.rs 的 `read_pi_settings`/`write_pi_settings`（现为私有）改 pub；helix.rs 的 `pi_set_package_enabled`（:495-531 内联解析+写入）、`pi_packages_enabled_map`（:438-444）、`pi_local_extension_patterns`（:729-735）全部改用 config.rs helper，消灭 3 份重复解析 + 双写者
2. **原子写**：config.rs 新增 `atomic_write(path, contents)`（tmp+rename，照抄 hooks.rs:232-238 现成模式），应用于：`write_pi_settings`、`write_pi_models`、`pi_set_package_enabled`、`helix_set_yaml_key`（helix.rs:100 直写）、`helix_set_delegation_identities`（:121）、`helix_set_config_key_value`（:177）
3. **过时注释修正**：paths.rs:168-172 的 `custom-providers.json` 改为 `models.json`（与实际不符）；api-settings.tsx MCP 保存处"写入 config.yaml"的过时文案改为 mcp.json

4. 备份目录保留，任何一条验证不过即可回滚
